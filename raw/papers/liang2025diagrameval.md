# DiagramEval: Evaluating LLM-Generated Diagrams via Graphs

**Authors:** Chumeng Liang, Jiaxuan You
**Affiliation:** University of Illinois Urbana-Champaign
**Venue:** EMNLP 2025 Main
**ArXiv ID:** 2510.25761 (October 2025)
**Code:** https://github.com/ulab-uiuc/diagram-eval
**License:** CC BY 4.0

## Abstract

The paper introduces DiagramEval, a novel evaluation framework for assessing diagrams generated by large language models. Rather than treating diagrams as generic images, the approach conceptualizes them as graphs, where text elements become nodes and connections become directed edges. Two new metric groups — node alignment and path alignment — assess how generated diagrams compare to reference diagrams. The authors validate their metrics against state-of-the-art LLMs on recent research literature and demonstrate superior explainability compared to existing metrics like CLIPScore. Code and datasets are made publicly available.

## 1. Introduction

Diagrams serve critical communicative roles in research papers, exemplified by the famous Transformer architecture diagram. Creating high-quality diagrams remains labor-intensive and complex. While standard image generation models struggle with clear, well-structured diagram creation, the authors propose leveraging recent LLM advances to generate diagrams directly as SVG code — a structured, text-based format. This approach enables "more fine-grained and explainable evaluation" compared to conventional image-level metrics.

Existing evaluation methods lack sufficient expressiveness. Most benchmarks employ diagram-level metrics originally designed for general image generation, failing to capture the "detailed logical correctness" that distinguishes diagrams. The authors identify a critical gap: metrics need to evaluate element-wise accuracy and logical relationships rather than overall visual similarity.

## 2. Related Works

The literature encompasses both scientific image understanding and generation. Current automated evaluation metrics fall into two categories: (1) diagram-to-diagram similarity metrics, and (2) caption-to-diagram similarity metrics. Both primarily measure overall similarity in latent space while neglecting "detailed logical accuracy, such as verifying element-wise connections against the paper context."

The VPEval metric represents the closest related work, using visual question answering to evaluate element and connection accuracy. However, VPEval "often struggles to accurately identify connections even in diagrams involving common knowledge, requiring manual annotations." The DiagramEval approach extends VPEval's concept by leveraging vision-language models and SVG file parsing for more reliable extraction.

## 3. Preliminary: Problem Definition

The diagram generation task is formulated with input corpus {T, c, π}, comprising:
- Original paper context T
- Original diagram captions (c_orig)
- Layout captions (c_layout)

The goal is generating a diagram D that demonstrates the research paper's overall idea. A ground-truth diagram D_gt serves as reference for evaluation. Diagrams are generated in SVG format, which is "both editable and widely adopted by proprietary LLMs."

## 4. Methodology

### 4.1 Constructing Diagram Graphs

The framework treats diagrams as text-attributed graphs (TAGs), where diagram elements with text become nodes and connections become directed edges.

**Node Extraction:**

A two-step process combines spatial and semantic factors. First, the system parses the SVG file, collecting spatial coordinates and span lengths of all text items. Text items are considered part of one node if their y-coordinates differ by less than K × font size (K=1.5 empirically) and their x-coordinate spans overlap by more than τ (τ=0.2 empirically).

Second, a lightweight vision-language model refines this draft node list through: (1) merging spatially contiguous and semantically related text nodes, (2) adding missing conceptual nodes (including non-textual elements like icons), and (3) removing nodes with unclear semantics.

**Edge Extraction:**

Since edges are represented implicitly in diagrams, manual rule-based extraction from raw SVG is "highly complex." Instead, an LLM with vision capabilities receives the rendered diagram image and curated node list. The model analyzes visual cues — arrows, lines, and proximities — to identify all directed connections between node identifiers, yielding directed edges E = {(v_i, v_j), ...}.

### 4.2 Evaluation Metrics

**Node Alignment:**

Assesses text element fidelity by evaluating how the set V_gen from generated diagrams aligns with V_ref from reference diagrams. Node matching occurs when textual similarity between node pairs exceeds a threshold.

Metrics computed:
- True Positives (TP_V): cardinality of matched node pairs |M_V|
- False Positives (FP_V): unmatched nodes in V_gen
- False Negatives (FN_V): unmatched nodes in V_ref

Performance quantified through Precision_V, Recall_V, and F1-score_V.

**Path Alignment:**

Evaluates node-wise structural fidelity by assessing whether paths exist in both generated and reference graphs among previously matched nodes. Comparison is restricted to subgraphs induced by matched nodes M_V.

For each ordered pair of distinct matched nodes (u,v): (1) whether a path exists from u to v in G_gen^M, and (2) whether a corresponding path exists in G_ref^M.

- P_gen = {(u,v) | u≠v, path from u to v exists in G_gen^M}
- P_ref = {(u,v) | u≠v, path from u' to v' exists in G_ref^M}

Metrics: TP_P = |P_gen ∩ P_ref|, FP_P = |P_gen \ P_ref|, FN_P = |P_ref \ P_gen| → Precision_P, Recall_P, F1-score_P. Using path existence (reachability) rather than direct edges captures indirect-but-valid information transfer.

## 5. Experiments

### 5.1 Experimental Setup

- **Generators:** Llama 4 Maverick, Gemini 2.5 Pro, Claude 3.7 Sonnet (official APIs). Layout captions via Gemini-2.0-Flash-lite.
- **DiagramEval setup:** Gemini-2.0-Flash-lite for node extraction refinement and edge extraction.
- **Baseline:** CLIPScore (SigLIP encoders). VPEval unsuitable: needs explicit text descriptions of objects; counts only direct connections.
- **Dataset:** Papers accepted by CVPR 2025 (post-cutoff for all LLMs); automated pipeline extracted 361 diagrams with abundant text annotation, plus captions and paper context.

Claude achieves best performance on four of six proposed metrics and CLIPScore (Image), but exhibits poor node alignment precision (0.2921) with outstanding recall (0.5087). Claude generates diagrams with average 31.67 nodes vs Gemini's 21.42 and Llama's 10.68 — extraneous nodes reduce precision while comprehensive coverage maintains recall.

### 5.3 Statistics

- Node Alignment correlates positively with CLIPScore (shared text-consistency focus) but has "healthier score distributions" by isolating node-level alignment from spatial layouts, colors, styles.
- Changing layout from vertical to horizontal can partially offset CLIPScore drops caused by removing ALL diagram connections — CLIPScore is oversensitive to superficial elements.
- Path Alignment shows minimal correlation with CLIPScore: many state-of-the-art LLM diagrams perform poorly at expressing relationships — a weakness never explicitly revealed by existing metrics.

### 5.4 Human Evaluation

**Edge extraction accuracy** (two ML researchers, one random edge per diagram):
- 85.87% of reference diagram edges extracted accurately (361 evaluated)
- 90% of generated diagram edges extracted accurately (300/361; 61 diagrams too low-quality for edge extraction)

**Correlation with human judgment:** 50 reference + Gemini-2.5-Pro generated pairs, two senior ML researchers, "Do two diagrams express the same logic?" good (1.0) / fair (0.5) / bad (0). Average similarity 0.3298; nearly half scored 0.

### 5.5 Case Study: Metric Divergences

1. **Low CLIPScore(Text), high Path F1:** correct explicit data flow (Path F1: 1) but different layout/icons (CLIPScore-Text 0.2558).
2. **High CLIPScore(Text), low Path F1:** no clear data flow (Path F1: 0) but includes all caption text → perfect CLIPScore(Text): 1. "The generator may hack the metric" — placing all text elements yields perfect scores through metric gaming.
3. **Low CLIPScore(Image) 0.6007, high Node F1 0.8696:** layout/icon differences depress CLIPScore despite correct text elements.
4. **High CLIPScore(Image) 0.8094, low Node F1 0.16:** CLIPScore overlooks element-wise logic differences.

## 6. Conclusion

DiagramEval introduces fine-grained, interpretable, structure-aware metrics for LLM-generated scientific diagrams via graph representation and node/path comparison. Existing metrics like CLIPScore suffer from over-sensitivity to visual elements and vulnerability to metric hacking.

## Limitations

LLM performance uncertainties: "the LLM may not reliably identify all edges in the reference graph, potentially causing inaccurate or underestimated evaluations." Still, the metrics reduce complex model dependency and offer more interpretable outcomes.
