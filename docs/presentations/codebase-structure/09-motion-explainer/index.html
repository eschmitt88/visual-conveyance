meridian — the shape of the codebase

A self-hosted read-later / RSS service, 13,710 lines of backend Python: a one-way ingest pipeline writes into one SQLite file, and an HTTP API, a web reader, and a CLI read it back out.

  1. One SQLite file is the hub — 1.8 GB, WAL mode, ~120,000 articles. Only store/ touches it; only writer.py writes.
  2. A one-way pipeline writes in: schedule → fetch → extract → dedup → store; p50 2.1 s until searchable.
  3. extractor.py is the caution zone: largest file, 14 fragile heuristics, and the codebase's one layering violation.
  4. Reads flow back out through the API — p50 28 ms; routes.py crams all 31 endpoints into one file.
  5. Web reader and CLI use the same HTTP API — no database backdoors. The frontend has zero tests.
  6. Five invariants keep it testable and replayable; the layering puts store/ at the bottom, api/ and cli/ on top.
  7. First changes land in pipeline/sources/ (4-file recipe) or api/routes.py — almost never in store/ or queue/.
