INC-1194 — anatomy of the June 24 outage

On June 24, 2026 a rewritten search query met two latent weaknesses — autovacuum debt and jitterless retries — and slow detection stretched a one-endpoint regression into a 4 h 17 m platform-wide partial outage; this is how, and what changes.

8 / 8Three P0 fixes land in Q3 2026 — latency alerts, pool alerting, jittered retries — one per failure leg.

space = play/pause · ←/→ = step
  1. 14:02: a deploy rewrites search into a leading-wildcard LIKE — no index can serve it; 0.4 ms becomes 24–31 s.
  2. Latent debt: 38.1 M dead tuples from a June 22 backfill push scans past the 30 s timeout — ~57% die.
  3. Failures retry every 1 s with no jitter — traffic ×4.7 — and the shared 80-connection pool saturates.
  4. Three legs align into a 4 h 17 m outage; remove any one and it is a degradation, not an outage.
  5. Detection lags 68 minutes: error-rate-only alerts, 1-in-100 sampling, and a broken deploy marker feed a network misdiagnosis.
  6. Rollback fails — the migration dropped the old index (rebuild ≈6 h); even a pool bump backfires.
  7. The feature flag stops the bleeding at 17:05; VACUUM and cache re-warm restore all SLOs by 17:53.
  8. Three P0 fixes land in Q3 2026 — latency alerts, pool alerting, jittered retries — one per failure leg.
