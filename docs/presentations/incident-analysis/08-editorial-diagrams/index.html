Anatomy of a 4 h 17 m outage

A rewritten search query landed on two latent weaknesses — autovacuum debt from a two-day-old backfill and jitterless client retries — and took ledgerline’s invoicing API down for 4 h 17 m; a wrong network theory cost 68 minutes, rollback was impossible, and a feature flag ended it.

One outage, three causes

PR #8841 added a leading-wildcard LIKE — a pattern no B-tree index can anchor — and moved org-scoping out of the SQL, so every search scanned all 274.2 M rows; the canary table holds ~2 M rows, ran the same scan in ~180 ms, and stayed green. Bloat from the June 22 backfill — 38.1 M dead tuples, the superseded row versions that Postgres’s background autovacuum cleanup reclaims, except its trigger threshold on this table is ≈54.9 M so it never ran — stretched 24–31 s scans past the 30 s timeout, and ~57% of searches died as errors.

Where 4 h 17 m went

The only alert watched error rate — search p99 had exploded at 14:07, four minutes before the 5xx alert — and a coincident cloud-provider packet-loss advisory anchored responders on a network theory for 50 minutes. Rollback died at 15:40 because migration 0412 had already dropped the covering index the old query needed (an index holding every column the query reads; rebuild ≈6 h — started 16:05 as insurance, done 21:48, after close), so the 90-second flag flip at 17:05 is what stopped the bleeding; search ran exact-match-only until the fixed, org-scoped contains search returned June 26.

Why it spread: the retry loop

Requests borrow one of 80 pgbouncer connections — a fixed, shared pool of database connections — so when the 15:00 wave of scheduled invoice-generation jobs pushed demand past the pool, every endpoint behind it (invoice creation, PDF rendering, webhook dispatch) queued behind 30-second scans from 15:12 until 17:18. A 16:20 bump to 200 connections backfired — more concurrent scans worsened write latency and it was reverted at 16:31 — because the holds, not the pool size, were the problem.

The three P0s each close a different leg of the failure: the alert gap that cost 68 minutes, the pool that spread the blast, and the retries that fed it. The P1/P2 tail hardens what made June 24 possible — the bloat, the bundled irreversible migration, and the broken instruments.

Blameless, by design: every decision was reasonable given what responders could see. The fixes target instruments and systems, not people.
