murmur — cheap reverb augmentation, and exactly where it stops working

The bet: ultra-cheap audio augmentations inspired by natural reverberation improve bird-call classification on small datasets — more per unit of compute than reaching for a bigger or pretrained architecture. A small CNN on log-mel spectrograms is held fixed as the control; only the augmentation pipeline moves. 6,200 clips, 34 heavily long-tailed species, one desktop GPU.

  • Partially supported, not clean. The best recipe lifts validation macro-F1 by +5.9 points, but the gain is concentrated in common species and barely touches the rare tail.
  • Not every "natural-reverb" augmentation helped. Pitch/time stretch actively regressed the model (to 0.589); SNR-controlled noise mixing alone was a null result (+0.002, inside seed noise ≈ ±0.006).
  • Best is a stack, not a single trick — light reverb + noise mixing + SpecAugment. Heavy reverb helped common classes only and came in below the stack.
  • Next move: class-conditional augmentation — apply the helpful transforms only where they help and protect the rare tail. Global augmentation has plateaued.

Two honest results in this ledger. exp-03 is a real regression — pitch/time warping smears the fine spectral cues the rare classes depend on, dropping below the no-aug baseline. exp-04 is a null: its +0.002 over exp-02 sits inside run-to-run noise (±~0.006 across seeds). It was kept in the stack on the bet that it composes with SpecAugment — which exp-05 bore out.

The dataset is heavily long-tailed by design: the 8 most common species are ~52% of clips; the top class (American Robin) has 480 clips while 11 species have fewer than 80, and 5 fewer than 45. Macro-F1 is the primary metric precisely because it weights the tail equally with the head.

Reproduces exp-05 (val macro-F1 0.671). The win came from data-space moves, not compute — these augmentations add well under a minute of wall-clock over the clean baseline.

backbone: small_cnn            # unchanged control across all experiments
input: logmel_128              # 128 mels, 25ms/10ms
train: {lr: 3e-4, batch: 32, epochs: 60, schedule: cosine}
sampler:
  class_balanced: 0.5          # partial reweight toward the tail
aug:
  reverb_ir:  {p: 0.5, rt60_range: [0.3, 0.6]}   # light, measured IRs
  noise_mix:  {snr_db: [5, 20], beds: [wind, rain, chorus]}
  specaugment: {freq_masks: 2, time_masks: 2}
  # pitch_shift / time_stretch: OFF (regressed the rare tail — exp-03)
  # heavy reverb: OFF (helped common classes only — exp-06)
Why a stack and not one trick? The components compose: noise mixing that was null alone becomes useful once SpecAugment is present, and the partial balanced sampler recovers a little tail recall. But decomposition shows ~4.5 of the 5.9 points come from common/mid tiers — the deep tail improved yet remains the ceiling.

The clear direction: stop augmenting globally, start augmenting per class — protect the tail from the transforms that smear it while keeping the head's gains.

  1. class-conditional-aug
    Apply each augmentation only to the tiers where the ledger shows it helps: light reverb everywhere, but pitch/stretch and heavy reverb excluded from rare/deep-tail classes. Direct test of the "condition on class" thesis. Est. ~1 h.
  2. sampler-vs-aug-ablation
    A clean 2×2 — (balanced sampler on/off) × (aug stack on/off) — to de-confound exp-05, where the sampler and augmentations were introduced in the same run. Cheap, ~4 runs × ~50 min.
  3. backbone-fairness-arm
    Finally run the architecture control: a larger / AudioSet-pretrained backbone with no augmentation at matched compute, to see whether murmur's +5.9 augmentation points beat what a bigger model buys. Settles H2. Est. up to ~6 h — the heaviest run, worktree overnight.
Honest caveat carried forward: the efficiency half of the hypothesis (H2 — augmentation is the better marginal spend than a bigger backbone) is still asserted, not shown: the fair bigger-backbone arm has never actually been run. The test split (~930 clips) also remains untouched — every number here is validation macro-F1, with a single held-out scoring pass reserved for after the recipe is frozen.
