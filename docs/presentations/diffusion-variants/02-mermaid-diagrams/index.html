Diffusion models: destroy carefully, learn to rebuild

Stable Diffusion, Midjourney-class systems, DALL·E 3, Flux — all generate images by learning to reverse a gradual noising process, and nearly every variant exists to make one thing cheaper: sampling.

The core mechanism

flowchart LR
  A["Real image"] -->|"forward process: add tiny noise, ~1000 fixed steps, no learning"| B["Pure noise"]
  B -.->|"training: a network learns to undo one small step"| C["Fresh random noise"]
  C -->|"generation: apply the learned step N times"| D["New image"]
  V["Speed variants"] -.->|"shrink N from ~1000 to as few as 1-4"| C
  classDef fixed fill:#eceff1,stroke:#607d8b,color:#263238
  classDef learned fill:#e3f2fd,stroke:#1e88e5,color:#0d47a1
  classDef outp fill:#e8f5e9,stroke:#43a047,color:#1b5e20
  class A,B fixed
  class C,V learned
  class D outp

A fixed process destroys real images into noise; a network learns to undo it one small step at a time (undoing all noise in one jump would be nearly impossible, a little is tractable); generation runs that learned step repeatedly from fresh random noise, so the output never existed anywhere — no photo is edited, no database consulted. Everything below answers one question: how do we take fewer steps?

Training: guess the noise

flowchart LR
  A["Real image"] -->|"noised in one shot, at a random level t"| B["Noisy image"]
  B --> N["Network"]
  T["Timestep t"] --> N
  P["Prompt embedding"] -->|"text-to-image models only"| N
  N -->|"guess the noise that was added"| E["Predicted noise"]
  E -->|"mean-squared error vs the actual noise"| L["Weight update"]
  L -.->|"repeat billions of times, one random noise level each"| A
  classDef fixed fill:#eceff1,stroke:#607d8b,color:#263238
  classDef learned fill:#e3f2fd,stroke:#1e88e5,color:#0d47a1
  classDef outp fill:#e8f5e9,stroke:#43a047,color:#1b5e20
  class A,B,T,P fixed
  class N,E learned
  class L outp

The prediction target can equivalently be the added noise (ε), the score (the direction that makes the image more probable), or a velocity (a defined image-noise mixture) — three interconvertible conventions — and the network itself is a U-Net in Stable-Diffusion-1/2-era models or a diffusion transformer (DiT) in newer ones like SD3 and Flux. High-noise examples teach global composition, low-noise ones fine texture, and there is no GAN-style adversarial balance to maintain — that stability is a big reason diffusion displaced GANs.

The variant zoo: fewer steps

flowchart TB
  DDPM["DDPM · ~1000 steps"] -->|"same trained model, deterministic sampler, bigger jumps"| DDIM["DDIM · 20-50 steps"]
  DDIM -->|"sampling is just solving an ODE: better solvers, no retraining"| ODE["DPM-Solver · 10-20 steps"]
  DDPM -->|"retrain on straight noise-to-image paths (SD3, Flux)"| RF["Rectified flow · ~20-30 steps"]
  ODE -->|"retrain a student to take big jumps"| DIST["Distilled · 1-4 steps"]
  classDef orig fill:#eceff1,stroke:#607d8b,color:#263238
  classDef sampler fill:#e3f2fd,stroke:#1e88e5,color:#0d47a1
  classDef retrain fill:#e8f5e9,stroke:#43a047,color:#1b5e20
  class DDPM orig
  class DDIM,ODE sampler
  class RF,DIST retrain

Blue = the same trained network with a smarter sampler (DDIM is deterministic — same starting noise, same image — which also makes generated images invertible and interpolatable, and is what a tool's "steps" slider defaulting to ~30 exposes); green = a retrained objective (flow matching / rectified flow straightens the paths; progressive, consistency, and adversarial distillation train big jumps, with latent consistency models giving ~4-step generation). Below ~10 steps undistilled models degrade visibly, above ~50 returns diminish rapidly, and 1-4-step distilled models pay a mild quality-and-diversity cost — the technology behind "real-time" generation demos.

Latent diffusion: run it compressed

  subgraph LSP["Latent space · 64×64×4 = 16,384 numbers"]
    NZ["Random latent noise"] -->|"the whole denoising loop, each step ≈48× cheaper"| CL["Clean latent"]
  end
  CL -->|"VAE decoder, one single pass"| IMG["512×512 image"]
  classDef learned fill:#e3f2fd,stroke:#1e88e5,color:#0d47a1
  classDef outp fill:#e8f5e9,stroke:#43a047,color:#1b5e20
  class NZ,CL learned
  class IMG outp

A 512×512×3 image is 786,432 numbers; a separately trained VAE (variational autoencoder — an encoder-decoder compressor, downsampling 8× per spatial dimension) maps it to 16,384 — roughly 48× fewer — and running diffusion there (2022) is what put Stable-Diffusion-class models on consumer GPUs. Costs are minor — a slight quality ceiling from the compression bottleneck (historically fine text and small faces, much improved in newer VAEs) plus one decode pass — and note the division of labor: the VAE only compresses and decompresses, the diffusion loop generates.

  P2 --> G
  G --> S["One guided step"]
  classDef fixed fill:#eceff1,stroke:#607d8b,color:#263238
  classDef learned fill:#e3f2fd,stroke:#1e88e5,color:#0d47a1
  classDef outp fill:#e8f5e9,stroke:#43a047,color:#1b5e20
  class X fixed
  class N1,N2,P1,P2 learned
  class G,S outp

The gap between the two predictions is "the direction the prompt pulls," and the guidance scale s exaggerates it: s = 1 means no guidance, s ≈ 7.5 is a common Stable-Diffusion default, and pushed too far (roughly s > 12-15 in classic SD) it produces oversaturated colors and burned-in artifacts. Higher s buys prompt adherence and more "typical"-looking images at the cost of diversity — and the two runs double the network evaluations per step, the honest cost metric (NFE).

Two honest caveats: rare near-duplication of training images has been demonstrated, essentially for images repeated many times in the training set — a real but exceptional memorization failure, not the mechanism — and image-to-image or inpainting modes do start from a user-supplied photo (partially noised, then denoised back), but only as an explicit variant. For distilled models, the intended 1-4 step count is part of the design, not a corner cut.
